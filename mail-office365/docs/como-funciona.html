Enviar correos con PDF adjunto vía Office 365

Una API en NestJS recibe un PDF y los datos del correo, y los entrega al servidor SMTP de Microsoft usando una cuenta de Office 365.

1. Flujo general

1 · ClienteEnvía un POST /mail/send con formulario multipart: destinatarios, asunto, texto y el PDF.
→
2 · ControllerMulter lee el PDF en memoria. Se valida tipo, tamaño y que empiece con %PDF-.
→
3 · DTOclass-validator comprueba que los correos sean válidos y que asunto y texto no estén vacíos.
→
4 · ServiceNodemailer arma el mensaje MIME y adjunta el PDF.
→
5 · Office 365smtp.office365.com:587 (STARTTLS) autentica y entrega el correo.

2. Piezas del proyecto

ArchivoResponsabilidad
main.tsArranca Nest y activa la validación global.
mail.controller.tsEndpoint POST /mail/send, recibe el archivo (FileInterceptor).
dto/send-mail.dto.tsReglas de validación de to, cc, subject, body.
mail.service.tsCrea el transporte SMTP y envía con el PDF adjunto.
.envCredenciales y configuración (nunca se sube a git).

3. Cómo se adjunta el PDF

El PDF no se guarda en disco: llega como Buffer en memoria y se pasa directo a Nodemailer, que lo codifica en base64 dentro del mensaje.

attachments: [{
  filename: file.originalname,
  content: file.buffer,
  contentType: 'application/pdf',
}]

4. Configuración de Office 365

  1. Usa un buzón real (o de servicio) de Office 365 que enviará los correos.
  2. En el Centro de administración de Microsoft 365: Usuarios → buzón → Correo → Administrar aplicaciones de correo electrónico y activa SMTP autenticado.
  3. Si la cuenta tiene MFA, crea una contraseña de aplicación y úsala como SMTP_PASS.
  4. Copia .env.example a .env y completa los datos.
Importante: Microsoft está retirando la autenticación básica de SMTP en Exchange Online y muchos tenants ya la tienen bloqueada o desactivada por defecto. Si el envío falla con error de autenticación (535 5.7.139), tu organización requiere OAuth2: usar Microsoft Graph API (POST /users/{id}/sendMail) con un registro de aplicación en Entra ID y el permiso Mail.Send. Esta versión usa SMTP por ser lo más simple; el controller y el DTO se reutilizan tal cual si luego cambias solo el service.

5. Uso

npm install
cp .env.example .env     # completa credenciales
npm run start:dev

curl -X POST http://localhost:3000/mail/send \
  -F "to=cliente@ejemplo.com,otro@ejemplo.com" \
  -F "cc=jefe@ejemplo.com" \
  -F "subject=Factura de septiembre" \
  -F "body=Hola, adjunto la factura." \
  -F "file=@factura.pdf;type=application/pdf"

Respuesta correcta:

{ "ok": true, "messageId": "<...@tudominio.com>", "accepted": ["cliente@ejemplo.com"] }

6. Seguridad y buenas prácticas

  • Las credenciales viven solo en variables de entorno.
  • Se limita el tamaño del PDF (MAX_PDF_MB; Office 365 admite hasta ~25 MB por mensaje).
  • Se verifica la firma real del archivo, no solo el tipo MIME que declara el cliente.
  • Los errores internos se registran en log pero no se exponen al cliente.
Antes de producción: este endpoint no tiene autenticación, así que cualquiera con acceso a la URL podría enviar correos desde tu cuenta. Protégelo (API key, JWT o red privada) y añade límite de peticiones (rate limiting).
